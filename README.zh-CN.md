# IBD Companion

[English](README.md) | [简体中文](README.zh-CN.md)

IBD Companion 是一个 AI 辅助、本地优先的 OpenClaw skill，用于私密整理
个人炎症性肠病（IBD）记录，包括克罗恩病和溃疡性结肠炎。它以本地结构化
SQLite 数据库保存病程信息，再通过 AI 提供自然语言记录和查询入口，降低长期
记录负担，并帮助用户在就诊前更清楚地整理病情，提高信息保存与医患沟通效率。

它是个人记录与计划辅助工具，不用于诊断、开药或替代紧急医疗服务。

## 主要功能

1. **AI 辅助的本地个人 IBD 病情数据库。** 将个人病情基本信息、生物制剂
   输注及对应查血数据、年度或大型复查和日常症状整理成可追溯的长期记录。
   用户可以直接通过自然语言对话记录或查询，不必手动操作数据库表。
2. **低门槛的日常症状与饮食记录。** 默认按需记录，例如“今天吃了什么、
   有什么对应症状”。可选每日提醒模式仍在完善，目前需要另行配置，默认关闭。
3. **探索个人可能敏感的食物或其他诱因（持续完善中）。** 长期积累排便、
   腹痛、腹胀、饮食、睡眠和压力等数据后，可进行个人规律的探索性比较；结果
   不能证明医学因果。
4. **AI 辅助整理检查资料和就诊信息。** 将抽血指标、肠镜、影像、病理、
   报告原文和已确认的医生结论关联到对应输注或复查，便于查询病程、生成摘要，
   并在就诊前整理更清楚的沟通材料。
5. **治疗与复查计划管理。** 跟踪输注排期、改期、完成状态、相关监测和年度
   或其他大型复查计划，不会擅自推断或改变治疗周期。
6. **本地隐私与医疗安全边界。** 真实健康数据保存在 Git 之外的本地 SQLite
   数据库中；系统用于记录、整理和描述性回顾，不用于自动诊断、开药或替代
   医生判断。

## 快速使用与实践建议

如果配置路径下尚不存在数据库，任一 CLI 在首次使用时都会创建空的私有数据库。
使用 OpenClaw 时，可以直接通过自然语言记录或查询，而不必手动操作数据库表。例如：

- “记录今天排便 2 次，偏软成形，腹痛 1 分，和平时一样。”
- “今天喝了咖啡，晚上有些腹胀。”
- “下次输注是什么时候？”
- “总结最近 30 天的症状、输注和检查结果。”

外部提醒默认关闭；只有经过明确配置后，才会实际发送通知。

## 首次建档（可选）

新用户可以立刻开始记录日常症状，也可以按需逐步设置：

1. 相对稳定的疾病基本资料；
2. 经医生明确确认的当前治疗计划；
3. 经医生明确确认的大型复查计划；
4. 个人“平时状态”的症状基线；
5. 可选的外部提醒。

每一步都可以跳过、以后再补。基本资料只放稳定的疾病背景；治疗和复查频率属于独立计划，必须来自已明确确认的医生安排。agent 应一次只询问一项，不得自行推断缺失的频率或医学事实。

### 从图片和报告录入

如需录入化验单、内镜报告、影像报告或出院小结，推荐搭配支持图片和 PDF 理解的
多模态模型。它可以协助从原始资料中整理适合保存到本地数据库的结构化信息。

保存前应核对原始报告中的数值、单位、该报告提供的参考范围和异常标记；叙述性所见
应保留原文，不确定的信息保持为空。仓库内的 Python 脚本本身不提供 OCR，图片/PDF
理解能力取决于所用 agent 平台和模型。

### 内置指标

新建数据库默认初始化以下 6 项药物无关的起始指标：

| 指标 | 默认单位 |
| --- | --- |
| C 反应蛋白（CRP） | mg/L |
| 血沉（ESR） | mm/h |
| 血红蛋白（HGB） | g/L |
| 白细胞计数（WBC） | 10^9/L |
| 血小板计数（PLT） | 10^9/L |
| 白蛋白 | g/L |

### 添加自定义指标

默认面板刻意保持药物无关。使用 agent 时，可以直接自然语言提出需求，例如：
“请把英夫利西单抗浓度加入我的长期追踪，数值型，单位 μg/mL。” agent 应先根据
真实报告或照护计划确认定义，再执行添加。对应的命令行写法是：

```bash
python3 scripts/ibd_db.py metric-add \
  --code infliximab_level \
  --name "英夫利西单抗浓度" \
  --value-type numeric \
  --default-unit "μg/mL"
```

`code` 应使用稳定的小写 `snake_case`。测量数值选择 `numeric`，文本型结果选择
`qualitative`。默认单位仅用于录入提示；每个实际结果仍保存原始报告中的单位、参考
范围和异常标记。指标定义不会被删除；如需停止新录入，使用
`metric-deactivate --code <code>`，历史结果会保留。

## 隐私模型

SQLite 数据库是唯一事实来源，默认保存在仓库之外：

```text
${IBD_DB_PATH:-${OPENCLAW_STATE_DIR:-$HOME/.openclaw}/private/ibd/ibd.sqlite3}
```

不要向 Git 提交数据库、附件、导出的报告、真实病历或可识别个人身份的健康信息。
仓库提供的 `.gitignore` 会拦截常见数据库文件和私有数据目录，但每次提交前仍应
人工检查待提交内容。

### 备份与恢复

数据库是一个私有 SQLite 文件。升级前和日常使用中，应定期在仓库外保存受加密或
访问控制保护的副本。避免在其他命令仍在写入时复制；所有命令结束后，可采用如下
本地示例：

```bash
cp ~/.openclaw/private/ibd/ibd.sqlite3 ~/PrivateBackups/ibd-YYYY-MM-DD.sqlite3
```

恢复时应继续私密保存备份，并通过 `IBD_DB_PATH` 指向该副本；或仅在另行保留安全
副本后再替换正在使用的数据库。不要将真实数据库附到 issue、提交或公开发布中。

## 环境要求

- Python 3.10 或更高版本
- Python 标准库中的 SQLite 支持
- 使用 skill 时需要 OpenClaw；命令行脚本也可以独立运行

不需要安装第三方 Python 包。

仓库发布版本（例如 `v0.1.0`）标识公开发布的代码快照；私有数据库始终按当前
schema 初始化和维护。

## 安装

将仓库克隆到 OpenClaw workspace 的 skills 目录：

```bash
git clone https://github.com/denniscriss/ibd-companion.git \
  ~/.openclaw/workspace/skills/ibd-companion
```

初始化或迁移私有数据库。这是推荐的首选步骤：

```bash
python3 scripts/ibd_care.py init
```

该命令为新用户创建当前的私有数据库结构。如果配置路径下尚不存在数据库，任一 CLI
在首次使用时也会自动创建空的私有数据库。

如需使用其他数据库位置，可为命令设置 `IBD_DB_PATH`：

```bash
IBD_DB_PATH=/path/to/private/ibd.sqlite3 python3 scripts/ibd_care.py init
```

## 命令概览

基础跟踪脚本负责症状、因素、指标定义、输注、检查、检查结果和内部提醒记录：

```bash
python3 scripts/ibd_db.py --help
```

照护上下文扩展负责疾病档案、治疗与复查计划、复查层级、报告、已确认评估和症状基线：

```bash
python3 scripts/ibd_care.py --help
```

使用命令前请先阅读 `SKILL.md`。其中规定了安全边界、唯一事实来源和明确确认要求，
用于防止不同医学含义的数据被混在一起。

## 测试

测试只使用临时数据库，不会接触默认的私有数据库：

```bash
python3 -m unittest discover -s scripts -p 'test_ibd_*.py' -v
```

## 安全边界

- 保留来源原文和未知值，不编造医学事实。
- 不根据症状、检查指标或因素比较推断疾病活动或因果关系。
- 不依据自动分析改变药物或治疗周期。
- 只有在明确、已确认的来源支持时，才记录医生评估。
- 出现紧急或危险信号时应寻求专业医疗帮助，而不是继续常规趋势分析。
- 外部通知必须由用户另行批准并配置。
